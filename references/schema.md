# schema: session-tracker (v0)

Follows the usual append-only JSONL patterns: `snake_case`, lowercase enums, `supersedes` for corrections (never rewrite a line). All timestamps ISO8601 (`Z` UTC accepted). Session identity = `{node, session_id}` (a single reference format everywhere). `node` = the node slug (its ssh alias, where the node is reached over ssh).

## Canonical layout (the canon, the `canon_path` of the config)

```
index.jsonl                         # GLOBAL, derived (projection of the md), regenerated by `stk index`
naming-map.yaml                     # GLOBAL, data: context->subject + concise tokens (see naming.md)
<node>/events.jsonl                 # append-only shard of the node
<node>/<encoded-project-path>/<session-id>.md   # per-session record
```

The "global log" is the union of the `<node>/events.jsonl`: each node owns only its own shard, so two nodes never clobber each other with rsync. Two installations that publish under the same node slug do: `publish` copies the staging over the slice as it is, the last one wins. `index.jsonl` is the only global resource, derived and regenerated single-writer on the canon.

## Per-session record `<session-id>.md`

Three layers: **frontmatter** (metadata+computed, driver-managed) · **`## extracted`** (LLM, rewritten at every advance) · **`## user_notes`** (sacred, never touched by agents).

```yaml
---
schema: v0
session_id: <uuid>
node: laptop                        # node slug (ssh alias)
project: shop-web                  # basename(cwd)
project_path: /path/to/shop-web
git_branch: main
lang: en                           # ISO 639-1, dominant language of the content
name: shop-checkout-fix            # canonical name (see references/naming.md). auto=custom-title/ai-title harness
name_source: auto                  # auto | user (user override from `stk close --name`: do not overwrite)
class: task                        # task | distill (see naming.md)
status: dormant                    # see status-taxonomy.md
status_source: auto                # auto | user (user override: do not overwrite)
dormancy_risk: high                # computed: high|medium|low
tags: [refactoring, ssh-config]    # auto-derived
links: [https://github.com/.../pull/123, ...]   # optional, populated by `stk close --add-link`
forked_from: {node, session_id}|null
distill_target: bot-skill          # class=distill only: target skill of the distillation (parent in forked_from)
children: [{node, session_id}, ...]
pilots: [{node, session_id, label?, confidence?}, ...]      # remote sessions piloted BY this one
piloted_by: [{node, session_id, confidence?}, ...]          # pilots that drive this one
started_at: <iso>
last_activity_at: <iso>
last_indexed_at: <iso>
last_indexed_uuid: <event-uuid>    # WATERMARK of the incremental delta
n_events: <int>
---
## extracted
goal: ...
summary: ...           # short sanitized synthesis (text search target)
done: - ...
open: - [ ] ...
decisions: ...
internal_branches: ...  # side tracks/sub-tasks opened in the same session

## user_notes
- 2026-05-29 (intent): ...   <!-- nid:<id> -->
- 2026-05-29 (future): ...   <!-- nid:<id> -->
```

## Events `<node>/events.jsonl`

Every event carries `node` (= owner of the shard).

- `{ts, node, event:"index", session_id, mtime, last_indexed_uuid}`: processing snapshot. The status is NOT here (it lives in the record + `status_change`).
- `{ts, id, node, event:"note", session_id, kind:"past|present|future|intent", text}`
- `{ts, node, event:"status_change", session_id, from, to, by:"user|auto"}`
- `{ts, node, event:"link", rel:"pilots", pilot:{node,session_id}, piloted:{node,session_id|null}, by:"user|auto", confidence:"low|medium|high", label?}`: lives in the shard of the **pilot**.

**Idempotence**: `note` keyed by `id`; `link` keyed by the (pilot, piloted) pair; `status_change` only on a real transition. The merge does an **upsert** into the records.

## `index.jsonl` (derived)

1 JSON line per session = projection of the filterable frontmatter fields (see `stk index`). It is not a source of truth: it is regenerated from the md. Sorted by `last_activity_at` desc.

## Local state (driver)

`<data_dir>` (default `~/.local/session-tracker/`):
- `node`: file with the local node slug, read after the `node` key of the config and `STK_NODE` and before the hostname (which is not reliable, e.g. a laptop whose hostname is a generic model name).
- `shard/`: mirror of the canon's `<node>/` (pull) + staging of the new records (publish).
- `canon/`: read-only mirror of the WHOLE canon (index.jsonl + all the `<node>/`), regenerated by `sync pull`. Source of the global queries on a non-canonical node; never used for writing (no publish from here).
- `primary-check/<key>.json`: cache of the remote side of `stk primary-check` (one per `primary_node:primary_path` pair, TTL `STK_PRIMARY_CHECK_TTL`, default 1800s). The local side is never cached. See `references/primary-check.md`.

Watermark: no separate `state.json`; the authoritative watermark is `last_indexed_uuid` in the md frontmatter (pulled into `shard/`). `stk scan` compares the last `uuid` of the source JSONL with the stored one -> new|changed|unchanged.
